# Stage 10 — memory, behavioural interviewing and the adaptive policy

Status: implemented and tested with **scripted / mock** candidates only. No real Ollama, Sentence-BERT or Docker run was possible in the build environment, and no human has rated anything. Section 8 is the plan for the Windows machine.

## 1. What changed, in plain terms
- The interviewer remembers what the candidate said earlier (projects, tools, years, challenges, assumptions) and can refer back to it, with restraint.
- There are three interview types: technical, behavioural/HR, mixed. The setup screen has one extra choice; technical stays the default.
- The fixed Easy→Medium→Hard ladder is replaced by a deterministic policy. `adaptive:false` in the create payload keeps the old ladder.
- Everything works without Ollama. A local model, when present, only proposes wording; every proposal is verified.

## 2. Interview memory (`src/demo/memory.py`)
- **Extraction** is rule-based. Each item stores the exact source turn, the exact character span, the quote, a confidence (high/medium/low) and a kind (project, tool, years_experience, achievement, challenge, example, assumption, explanation, preference…).
- **Everything is a candidate claim** (`verified=False`). The interviewer never states a memory as fact; it quotes it ("You mentioned …").
- An optional LLM extractor was **not implemented**. Do not describe memory extraction as model-based.
- **Dedupe/contradiction:** same slot + same value merges; conflicting `years_experience` or `tool:<name>` negations open a contradiction, which becomes a non-accusatory clarification quoting both statements. Metric differences are deliberately not auto-flagged.
- **Retrieval:** TF-IDF cosine by default; Sentence-BERT only when `SMART_DEMO_MEMORY_SBERT=1` and the model is cached. No new vector store. Topic links reuse the existing RAG search with score floors (`BM25_MIN=6.0`, `SEMANTIC_MIN=0.45`) that are **heuristics, not calibrated for SBERT**.
- **Restraint:** at least 2 turns between references, at most 4 references per interview, minimum relevance 0.2, and a shared-word guard unless topic-linked.
- **Lifecycle:** stored inside the session JSON, so it survives a restart, expires after 14 days and is deleted with the session. Sessions never read each other's memory. Instruction-like text, links and code are never stored as memory (prompt-injection guard).

## 3. Behavioural interviewing (`src/demo/behavioural.py`, `behavioural_data/`)
- Versioned rubric (`competencies_v1.json`) and original question bank (`questions_v1.json`), 9 competencies, 36 questions; provenance in `POLICY.md`. No third-party question banks.
- STAR-inspired evidence: situation, task, action, result, ownership, quantified result, reflection — each with an exact quote span. Missing elements are *gaps to probe*, not penalties.
- Probe policy: ≤2 probes per example, ≤4 per interview, rotating wording; a second probe only for action/result/reflection.
- Mixed: 3 technical + 3 behavioural with a spoken transition. JD terms only influence selection; the JD text itself is not stored.
- Feedback is qualitative: no hire/reject language, no percentages, no scores, nothing about protected characteristics.

## 4. Adaptive policy (`src/demo/policy.py`)
Decisions: `deeper, clarify, explore_related, revisit, new_competency, practical, wrapup`. Priority: time → clarify → refused → weak → revisit → strong → practical → explore_related. Signals are keyword coverage, length and uncertainty cues. **These signals cannot tell a fluent wrong answer from an alternative valid one** (both show low exact-word coverage), so the policy only eases or deepens the next question and never says "wrong". Semantic similarity is never presented as correctness.

Next-question choice comes from the vetted RAG bank (same domain, unasked, not near-duplicate), ranked by difficulty distance, memory link, topic preference and retrieval rank. The time budget (default 45 min) can trigger a wrap-up.

## 5. Verification layer
Every proposed question (model or deterministic) passes: length, no instruction-like text, no links/code, no repeat of an earlier question, memory references must cite a known stored item and appear in the question. Rejections are logged as reason codes only. Ollama missing or slow → deterministic path (prompt version `10.fu3`).

## 6. Model decision
`llama3.2:3b` remains the latency baseline (Stage 9D: about 2.4 s warm median, 8/8 rule-accepted). `qwen2.5:7b` was 7/8 at about 11.4 s. Neither has been measured for Stage 10 prompts. **No superiority claim is made.** The provider and model stay configurable.

## 7. Privacy
Candidate text never goes to logs, Prometheus metrics, MLflow or the reports (test: `tests/app/test_stage10_eval_and_privacy.py`). New metrics carry codes only: `smart_memory_items_total`, `smart_memory_references_total`, `smart_policy_decisions_total`, `smart_behavioural_probes_total`.

## 8. Windows real-model validation plan
Run on the Windows machine (Ollama running, models pulled):
1. `python scripts\stage10_eval_suite.py` — repeats the scripted gates (mechanics only).
2. `python scripts\stage10_verify_real_stack.py --models llama3.2:3b qwen2.5:7b --runs 3 --mlflow --sbert` — real acceptance, fallback rate, latency, cold load, memory citations. Writes a blind review sheet and a separate key.
3. Calibrate `BM25_MIN` / `SEMANTIC_MIN` on SBERT with real transcripts, then record the chosen values.
4. Two raters score `docs/stage10_review/review_sheet.csv` independently without the key; report agreement. LLM judgements are not ground truth.
5. Only then compare models, and only on the measured numbers.

## 9. Known limitations
Heuristic floors uncalibrated for SBERT; no LLM memory extractor; coherence is a word-overlap proxy; no real latency numbers; no human validation; frozen modular evaluator still cannot be promoted.

## 10. Stage 10D-F repairs (prompt `10.fu4`)
**Schema.** One compact JSON object: `decision` (ask|skip), `question`, `purpose`, `concept_id`, `answer_quote`, `memory_id`, `skip_reason` (one of `irrelevant`, `redundant`, `unsupported`, `answer_complete`, `none`). A skip costs a few tokens. The old self-report booleans are gone (they contradicted each other and caused `self_report` rejections). `num_predict` is `FL.num_predict()` = 224 (env `SMART_DEMO_FOLLOWUP_NUM_PREDICT`); 160 truncated larger models' JSON (`reply_truncated`).
**Memory citation.** `memory_id` must be an id that was offered in the prompt, which in turn comes from a stored candidate statement. The question does NOT have to quote it; an unknown id is a `memory:unknown_id` rejection. When a citation is unsupported but the question is otherwise fine, the citation is dropped (`memory:citation_dropped`) and the question is asked without a memory reference. A question that sounds like "earlier you said ..." without an offered, valid id is rejected as fabricated. Reference positions are the positions the candidate actually saw.
**Continuity and themes.** `policy.continuity_pick` builds a harder same-topic question from an earlier, unreferenced explanation (scenario B); `policy.THEMES` maps project/challenge/team statements to natural wording (scenarios A, C). Scenario D asks for clarification without calling either statement false; scenario E asserts that nothing is referred to.
**Sentence-BERT.** The repeated loading lines were real reloads. `memory.shared_sbert` caches the encoder per process (never per-session memory); counters are in `memory.MODEL_STATS` (`loads`, `cache_hits`, `load_failures`) and `memory.reset_model_cache()` resets it for tests.
**Observability (no answers logged).** Per call: model, eligible opportunity class, accepted/skip/fallback, skip reason, rejection codes, memory-citation validity, generated tokens, `done_reason`, latency, provider failures, model-load counters. New metric names are in `src/mlops/metrics.py` (six KNOWN names).
**Harness.** `src/demo/eval_data/stage10f_opportunities_v1.json` (40 cases, 4 interviews, written before any model ran) and `src/demo/opportunity_eval.py`. Four classes: `expected`, `skip`, `memory_use`, `memory_inappropriate`. Success is counted per ELIGIBLE opportunity (`expected` + `memory_use`) and is audit-clean (independent of the validator). Run scripted: `python scripts/stage10f_eval.py`; real: `scripts/stage10_verify_real_stack.py --opportunities`. The scripted stand-in follows the prompt's exact-words hint; its numbers are a plumbing check, not model performance.

## 11. Stage 10G-I: what the real llama3.2:3b run changed (prompt `10.fu5`)
Evidence: `reports/stage10_windows_evidence/` (Windows, Ollama 0.32.13, prompt 10.fu4: 12 of 23 eligible useful, 8/11 skips right, 0 fabricated memory references). Analysis: `reports/stage10_ghi_eval/windows_failure_analysis.md`.
**Who decides what.** Code decides whether a concept is already covered (exact words OR word stems: `Context.soft_found`, `_stem`). All shown concepts covered -> skip by the rules, the model is not called (`decided_by: rules`). Otherwise code picks ONE `TARGET` concept (`target_concept`) and the model only writes the wording; its schema still allows `skip` for `off_topic` / `nothing_to_add`. A model `skip` with reason `covered` while the hint says a concept is open is overruled (`skip:covered_contradicts_hint`) because llama3.2:3b did exactly that on 6 of 6 such turns. `SMART_DEMO_FOLLOWUP_TRUST_MODEL_SKIP=1` turns the override off.
**New wording rules (fixed regexes/sets, no model):** `question:closed_yes_no` (the sentence or its last clause starts with an auxiliary verb and nothing invites an explanation; "Can you elaborate ..." is allowed), `question:generic_definition_request` now also covers "what does it mean / what is meant by", `question:restates_answer` (every content word is already in the answer or the original question and no memory is cited). A concept id written into the question ("how does E2 ...") is replaced by the concept label (`sanitise_ids`); an unknown code-like token is still rejected.
**One repair attempt.** Only when EVERY rejection is a fixable wording problem (the codes above, `question:not_tied_to_answer`, `question:novel_terms`, `skip:covered_contradicts_hint`) and at least 2 s of the deadline remain, the model is asked once more with a one-sentence correction. Any safety rejection (invented memory, unknown id, injection, accusation, invalid JSON, truncation, timeout) is never repaired: the deterministic follow-up is used. Logged as `attempts`, `repaired`, metric `smart_followup_repairs_total`.
**Memory.** Citation rules are unchanged (offered id only, traceable to a stored candidate statement, fabricated "earlier you said ..." rejected). The prompt now says the listed statements were selected as related to the topic.
**Evidence for the next run.** `scripts/stage10_verify_real_stack.py --opportunities` now writes `rows[]` per case (outcome, reasons, skip reason, rule vs model decision, attempts, offered memory ids, and the model's rejected replies on the synthetic set), the nine evaluation dimensions, model details from `/api/show` and the Ollama version. Candidate answers never go to MLflow (counts only).
**Unchanged:** the 40-case set and its labels (a test pins its hash), the eligibility rules, the scoring formula.

## 12. Stage 10J-L: memory contract, technical questioning, evaluator integrity (prompt `10.fu6`)
Evidence: `reports/stage10_windows_evidence_2/` (Windows, llama3.2:3b, prompt 10.fu5: 11/23, memory use 0/7). Full analysis: `reports/stage10_jkl_consolidated_report.md`; case-by-case: `reports/stage10_jkl_eval/windows_comparison.md`.
**Memory mode.** When retrieval offers a usable statement, the first call is a memory attempt: the model sees ONE earlier statement (id, turn, quote) and writes only the question; `memory_id` is `<that id>` or `none`. Code cuts the stored claim out of its own lead-in (`memory.recall_lead`) and adds "Earlier you said you ..." itself, so the sentence is always a real stored claim and an id never reaches user text. A question that uses words only found in a stored statement without citing it is rejected (`memory:uncited_reference`), as is a second lead-in (`memory:double_reference`). A declined or rejected memory attempt falls back to a standard question and the memory test is marked unsuccessful (stage `declined` / `not_connected` / `rejected`).
**Retrieval.** The query now holds the question, topic, answer sentences, vetted concept labels and the reference; relevance is shared distinctive words (the stored quote counts), theme or a semantic floor. Lexical only in the sandbox; Sentence-BERT behaviour must be confirmed on Windows.
**Telemetry.** `failure_type` = retrieval | generation | citation_metadata; `memory_stage`; metric `smart_followup_memory_stage_total{stage}`.
**Technical questioning.** Concept depth is absent | mentioned | explained (sentence-level, lexical; NOT a correctness score). `ignores_target`, `targets_covered_concept`, `payload:skip_with_question`; repair text quotes the rejected question; fallback classes not_attempted | model_error | payload_inconsistent | wording_failed | no_followup_needed.
**Evaluator.** One formula (`score_row`); skip success needs no follow-up; B07 is a fixture defect (class skip, `followup: null`) scored on safety only and excluded from strict rates, label unchanged and awaiting approval. Review pack v2 is blind and UNRATED. Fixture hash pinned.

## 13. Stage 10M: evidence-based corrective cycle (prompt `10.fu7`)
Full report: `reports/stage10m_consolidated_report.md`. **Technical terms:** a token is no longer "new" when it is an ordinary hyphenated compound, an acronym of a phrase in the allowed material, or occurs in the curated bank for the same domain (`followup_llm.novel_technical_terms`; every exception is written to the proposal's notes). **Evidence:** a paraphrased `answer_quote` is replaced by the verbatim answer sentence it most likely meant (`evidence:quote_replaced_by_code`); a quote that matches nothing is still rejected. **Ids:** E/S/G/K and memory ids are replaced in any case or rejected (`question:id_leak`). **Wrong premise:** `knowledge/concept_equivalences_v1.json` lists names for one thing; asking how they differ is rejected (`question:false_premise`). **Payload:** `skip_reason` is no longer required by the schema; an ask carrying one is normalised and noted. **Retry:** a memory-mode repair keeps the statement, its id and the instruction to keep it. **Lead-ins:** an explanation lead names the topic only if the candidate's words contain it; otherwise it quotes them. **Offline engine:** BM25 ranking only (`sim.bm25_search`), so scripted tests do not depend on Sentence-BERT being installed. **Restart:** the legacy scorer is reloaded lazily (`DemoEngine._load_scorer`).

## 14. Stage 10N: evidence chosen by code (prompt `10.fu8`)
Full report: `reports/stage10n_consolidated_report.md`. **Evidence contract.** The model is no longer asked for `answer_quote`; `evidence:none_verified` cannot be produced. `code_evidence` picks the verbatim answer (or offered-memory) span; a quote the model still writes is telemetry only and neither voids a question nor counts as a tie. **New checks:** `reveals_reference_value` (value-like gaps such as "O(n²)" are shown to the model as a neutral label and may not be stated), `presupposes_claim` ("Since X ..."), `repeats_answer_content` (three quarters of the question is the candidate's own words and it adds no open concept), `memory_link_without_gap`, `id_leak`, `false_premise`. **Engagement** with an open concept now accepts a stem ("equal"/"equality") or two words from the curated reference sentences about that concept. **Bug fixes found by holdouts:** a bare "wrong" no longer counts as accusatory ("what could go wrong"); "earlier results" is not a memory reference. **Evaluation:** `src/demo/question_pairs_eval.py` + `scripts/stage10n_pairs_eval.py` judge hand-written good/bad questions (not human validation). The frozen fixture is unchanged.

## 15. Stage 10N Windows regression repair
Full report: `reports/stage10n_windows_regression_repair.md`. **Time budget:** no follow-up (rule, memory or model) is added, and no model call is made for one, once the budget is spent (`DemoEngine._budget_spent`). **Endpoint errors:** in `ollama_stream`, a connect timeout is `ProviderUnavailable` (unreachable); only a timeout after connecting is `DeadlineExceeded`. **Prompt size:** the follow-up user prompt is trimmed in a fixed order (BUILD ON, USE, previous questions, shorter question) to stay under 2900 characters. **Tests:** `tests/app/conftest.py` makes candidate-question ranking BM25-only unless a test installs its own service or is marked `real_stack`, because the default service becomes Sentence-BERT + FAISS where those are installed. `scripts/stage10n_windows_repair_diag.py` prints what a machine does for each of the five failures.
