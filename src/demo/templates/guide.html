How to read the labels

Every result on these pages says where it came from. Five situations are kept visibly apart.

Operational flow

Setup, the interview conversation, progress and the feedback report. This never depends on any scorer: if a scorer or the experimental evaluator fails, the interview carries on.

SENTENCE-BERT

The only similarity scorer for new interviews. It measures how close an answer is to a reference answer and appears only in the optional technical details. This demo never adapts questions to it.

REAL MODEL MOCK VERIFIER

Experimental modular evaluation (opt-in). A model labels which required concepts your answer states, with your own words as evidence; fixed rules turn that into a rubric. MOCK uses a rule-based test double: it shows the pipeline, not answer quality. REAL uses a local model and is slow.

EXPERIMENTAL CODE CHECK

Opt-in and separate from every score. For a few Python questions it lists, in five groups, what was verified by running tests (only in an isolated sandbox, never in this web server), what the code contains, what is missing, what is incorrect and what is unverified (explanations are matched by wording only). If no sandbox is set up the code is only read, and the page says so. It gives no score and never affects anything adaptive.

ADVISORY ONLY

Most questions have no penalty-eligible scope. You get verified findings and feedback but no number, by design.

Abstained / unavailable

When the evidence is not enough to decide, the evaluator says so and gives the reason (the model could not decide, the evidence check rejected a finding, the answer was off-topic, or the model service failed). It never invents a score.

NOT human-validated

No score or finding here has been checked against human judgement. "Internally consistent" describes the evaluator's own evidence, not accuracy. The recorded run failed its acceptance gate (abstain rate 0.45 > 0.40).
